# 命令速查（aimcc-blog 项目专用）

> 按**使用场景**组织，不按工具。命令里的路径是原开发机路径，换机后 clone 到哪就换成哪。
> 三条口诀先记：**凡 500 先看日志；改配置必须重启验证；迁移文件永不修改。**

---

## 场景一：日常写代码（每次开工/收工）

```bash
git status                        # 看改了什么（开工先看一眼）
git add -A                        # 暂存全部改动（或者精确点名某个文件）
git commit -m "feat(server): 干了什么"   # 提交（-m 后面写人话）
git push                          # 推送
git pull --rebase origin main     # ⭐ 推送被拒时（队友先推了）：拉取排队合并，再 push
```

推送被拒的完整救援三连：

```bash
git fetch                                          # 看远程状态
git log HEAD..origin/main --oneline                # 队友推了什么
git pull --rebase origin main && git push          # 排队合并 + 重推
```

## 场景二：模块完成 → 部署三连（服务器更新）

```bash
# Mac / 个人电脑：
cd ~/Desktop/aimcc-blog/server                    # 新电脑换成你 clone 的路径
./mvnw clean package -DskipTests                  # 打包（skipTests=跳过测试，部署打包惯例）
scp target/server-0.0.1-SNAPSHOT.jar root@47.96.92.202:/opt/blog/blog.jar
                                                  # 上传到服务器正规驻地

# ssh 登录服务器后：
systemctl restart blog                            # 重启服务（新 jar 生效）
```

## 场景三：服务器排障（接口 500 / 异常 / 想看状态）

```bash
journalctl -u blog -n 50 --no-pager               # ⭐ 凡 500 第一动作：看最近 50 行日志
journalctl -u blog -f                             # 实时滚动日志（Ctrl+C 退出，服务不受影响）
systemctl status blog --no-pager                  # 服务活着吗（找 active (running)）
curl http://localhost:8080/api/articles           # 服务器本机自测接口
ps aux | grep blog.jar                            # 应用以哪个用户身份在跑（应为 blogapp）
free -h                                           # 内存还剩多少（1G 小机器常看）
```

## 场景四：服务器上的数据库（应急用；平时建表查数在 DBeaver）

```bash
mysql aimcc_blog -e "show tables;"                            # 有哪些表
mysql aimcc_blog -e "select id, title, status from article;"  # 直接查数
mysql -u blog -p aimcc_blog                        # 交互式进库（-p 后输密码，先验钥匙再开火）
```

```sql
-- Flyway 对账本（迁移跑没跑、对不对）
select version, description, success from flyway_schema_history;
```

## 场景五：SSH 与服务器通道

```bash
ssh root@47.96.92.202                              # 登录（密钥免密；新机器走密码）
ssh -o PubkeyAuthentication=no root@47.96.92.202   # 强制走密码通道（测试用）
```

## 场景六：改了服务器配置之后（systemd / ssh 配置类）

```bash
systemctl daemon-reload        # 改了 *.service 文件后必须执行，否则改动不生效
systemctl restart ssh          # 改了 ssh 配置后重启（改配置前先确认手里有备用通道！）
```

## 危险动作黑名单（每次执行前默念）

| 动作 | 风险 |
|---|---|
| `systemctl restart ssh` | 可能把自己锁外面——**先开第二个窗口保持连接**，或用控制台网页终端兜底 |
| `drop table` / `truncate` | 数据当场蒸发 |
| 修改已执行的 Flyway 迁移文件 | 下次启动校验和不匹配，拒绝启动 |
| 把密码写进任何文件/git | 泄露事故（密码只走环境变量和控制台输入） |
| 链式调用新代码 | 用户可读性规矩：显式循环平铺直叙 |
