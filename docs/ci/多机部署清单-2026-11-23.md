# 多机部署清单（2026-11-23）

> 目标：把 public 服务单独放到第二台机器上，网关仍然能把它当普通副本轮询。
> 前提：注册中心（Eureka）已经跑通，网关路由已经是 `lb://blog-public-service`。
> 本文是**操作清单**，不是原理说明；原理见《微服务拆分收尾》相关章节。

---

## 0. 一句话结论

跨机器能成立，靠的是「注册中心把地址变成动态数据」，但真正搬过去要手工解决三件事：

1. **网络**：容器网络是单机的，跨机器只能走宿主机 IP + 端口映射
2. **注册地址**：`prefer-ip-address` 注册的是容器内网 IP（`172.18.x`），别的机器连不上，必须显式指定宿主机 IP
3. **数据源**：数据库 / Redis 在 A 机，B 机的服务要写 A 机的 IP，并且 A 机要放行

---

## 1. 目标拓扑

```
                    ┌─────────────────── A 机 192.168.1.10 ───────────────────┐
公网 ──► nginx:80 ──► gateway:8080 ──┐
                    │  eureka:8761  ◄──┼── 注册 / 拉名单
                    │  mysql:3306   ◄──┼── 数据
                    │  redis:6379   ◄──┼── 缓存 / 会话
                    │  admin:8082       │
                    └───────────────────┼──────────────────────────────────────┘
                                        │
                    ┌─────────────────── B 机 192.168.1.20 ─┐
                    │  public:8081  ────────────────────────┘
                    └────────────────────────────────────────┘
```

- nginx、gateway、eureka、mysql、redis、admin 留在 A 机
- public 搬到 B 机
- **公网只暴露 A 机的 80**，其余端口只在安全组内网互通

## 2. 第一阶段：网络与防火墙

### 2.1 阿里云安全组（A 机）

只加**内网**规则，源地址填 B 机内网 IP，不要开 `0.0.0.0/0`：

| 端口 | 用途 | 源 |
|---|---|---|
| 8761 | Eureka 注册/查询 | 192.168.1.20 |
| 3306 | MySQL | 192.168.1.20 |
| 6379 | Redis | 192.168.1.20 |

### 2.2 阿里云安全组（B 机）

| 端口 | 用途 | 源 |
|---|---|---|
| 8081 | public 被网关调用 | 192.168.1.10 |
| 22 | SSH（CI 部署用） | 你自己的出口 IP |

### 2.3 检查连通性

在 B 机上执行：

```bash
nc -zv 192.168.1.10 8761
nc -zv 192.168.1.10 3306
nc -zv 192.168.1.10 6379
```

三个都通了再往下做，不通就别改代码——先解决安全组。

## 3. 第二阶段：让 A 机的注册中心对外

现在生产 compose 里 eureka **没有映射端口**（只给容器网络内用）。跨机器必须映射：

```yaml
  eureka:
    ports:
      - "8761:8761"      # 新增：B 机要能访问
```

改完重建：

```bash
cd /opt/blog-compose
docker compose up -d eureka
curl -s http://127.0.0.1:8761/eureka/apps | head -5   # A 机自检
```

在 B 机上验证：

```bash
curl -s http://192.168.1.10:8761/eureka/apps | head -5
```

> 注意：映射到 `0.0.0.0` 意味着同 VPC 内都能访问。必须靠安全组限制来源，
> 不要把 8761 暴露到公网。

## 4. 第三阶段：B 机的 public 配置

B 机只跑 public 一个服务。compose 文件放在 `/opt/blog-public/docker-compose.yml`：

```yaml
services:
  public:
    image: crpi-f7ypz0n6qfy16uva.cn-beijing.personal.cr.aliyuncs.com/ckaicraft/aimcc-blog-public:latest
    restart: unless-stopped
    ports:
      - "8081:8081"                     # 必须映射：网关是通过宿主机 IP:8081 访问它的
    environment:
      # 数据源指向 A 机，不能用服务名 mysql / redis
      SPRING_DATASOURCE_URL: "jdbc:mysql://192.168.1.10:3306/aimcc_blog?serverTimezone=Asia/Shanghai&characterEncoding=utf8"
      DB_USERNAME: blog
      DB_PASSWORD: root1234
      SPRING_DATA_REDIS_HOST: 192.168.1.10
      SPRING_DATA_REDIS_PORT: 6379
      REDIS_PASSWORD: root1234
      # 注册到 A 机的 Eureka
      EUREKA_URL: "http://192.168.1.10:8761/eureka"
      # 关键：注册出去的是「宿主机 IP + 映射端口」，不是容器内网 IP
      EUREKA_INSTANCE_IP_ADDRESS: "192.168.1.20"
      EUREKA_INSTANCE_NON_SECURE_PORT: "8081"
    healthcheck:
      test: ["CMD", "wget", "-q", "-O-", "--timeout=3", "http://127.0.0.1:8081/api/actuator/health"]
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 30s
```

三个易错点：

1. **不要写 `depends_on: mysql / redis / migration`**：它们在 A 机，B 机没有这些服务，写了会直接起不来。
2. **必须映射 8081**：不映射的话，即使注册了 `192.168.1.20:8081`，A 机的网关也连不进去。
3. **`EUREKA_INSTANCE_IP_ADDRESS` 必须显式给**：默认的 `prefer-ip-address: true` 会注册容器 IP `172.x`，跨机器不可达。

改完之后在 A 机的 application.yaml 里也可以显式覆盖，避免依赖环境变量名：

```yaml
eureka:
  instance:
    ip-address: ${EUREKA_INSTANCE_IP_ADDRESS:}
    non-secure-port: ${EUREKA_INSTANCE_NON_SECURE_PORT:${server.port}}
```

> Spring Boot 会把 `EUREKA_INSTANCE_IP_ADDRESS` 自动映射成
> `eureka.instance.ip-address`，环境变量其实可以直接用，上面的 yaml 只是写明默认值。

启动：

```bash
cd /opt/blog-public
docker compose up -d
docker compose logs -f public | grep -i "registration status"
```

看到 `registration status: 204` 就是注册成功。

## 5. 第四阶段：验证

### 5.1 名册里出现两个 IP

在 A 机执行：

```bash
curl -s http://127.0.0.1:8761/eureka/apps | grep -E "<app>|<ipAddr>|<status>"
```

期望看到 `BLOG-PUBLIC-SERVICE` 有两条记录，`ipAddr` 分别是 A 机的容器 IP 和一个
`192.168.1.20`（B 机宿主机 IP）。

### 5.2 网关能打到 B 机

```bash
for i in $(seq 1 10); do
  curl -s -o /dev/null -w "%{http_code} " "http://127.0.0.1/api/articles?page=1&size=1"
done
echo
```

期望 10 个 200。如果一半是 500，说明 B 机的 8081 从 A 机连不通（回第 2 步查安全组）。

### 5.3 摘除窗口仍然存在

停掉 B 机的 public：

```bash
docker compose stop public
```

- 立刻请求：会出现 500（网关还在轮询它）
- 约 90 秒后：全部恢复 200（租约过期被摘除）

这个窗口和单机多副本时完全一样，不是跨机器引入的新问题。

## 6. 第五阶段：CI 怎么改（可选，先手工也能跑）

现在的流水线只认一台服务器（`secrets.SERVER_IP`）。加第二台后有两种做法：

**做法一（省事）**：B 机手工部署。CI 只负责构建推送镜像，B 机上手动
`docker compose pull && docker compose up -d`。适合偶尔发版。

**做法二（自动）**：加一个 secret `SERVER_IP_B` 和对应 SSH key，在 `Deploy backend`
后面追加一步：

```yaml
      - name: Deploy public to second host
        run: |
          ssh root@${{ secrets.SERVER_IP_B }} "cd /opt/blog-public && docker compose pull public && docker compose up -d public"
```

注意两点：

- B 机也要能登 ACR：`docker login` 的凭据要单独配一次（或把 config.json 同步过去）
- 两个 SSH key 不要复用，B 机单独一把，泄露时好回收

## 7. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 名册里有 B 机，但请求一半 500 | B 机 8081 没映射，或安全组没放行 | 查 `nc -zv`、查 `ports:` |
| 名册里的 IP 是 `172.18.x` | 用了默认的 `prefer-ip-address` | 显式 `EUREKA_INSTANCE_IP_ADDRESS` |
| B 机 public 起不来，报连不上 mysql | 还在写服务名 `mysql` | 改成 `192.168.1.10:3306` |
| 页面能开但登录状态丢失 | 两台机器时钟偏差导致 JWT/会话过期异常 | 都开 NTP（`chronyd`/`systemd-timesyncd`） |
| 注册中心一重启，全站 503 约 90 秒 | 单节点 Eureka，名单被清空 | 接受，或配第二个 Eureka 做 peer |

---

## 8. 回滚

只回滚 B 机，不动 A 机：

```bash
# B 机
docker compose down
```

名册里 B 机的实例会在 90 秒内自动消失，网关回到只打 A 机。
**不需要改任何代码或配置**——这点比早期 nginx 写死地址的方案强。

---

## 9. 什么时候才值得做这一步

- 单机 CPU 打满（现在 2 核，public 已经占一核左右）
- 需要“一台机器维护时另一台继续服务”
- 想练手多机编排 / 后续上 K8s

如果只是博客访问量低、机器没跑满，**保持单机双副本更划算**：省一台机器的钱，
少一层网络延迟，排障也简单。
