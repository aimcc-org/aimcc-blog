## 1. 当前拓扑

```
              访客
               │ 80
        ┌──────┴─────────────────────── A 机：阿里云 ECS（杭州）47.99.174.185 ──┐
        │  nginx:80 → gateway:8080 ──┬─ lb://blog-public-service ──┐            │
        │                            └─ lb://blog-admin-service ──┐│            │
        │  eureka:8761（名册）                                     ││            │
        │  mysql:3306   redis:6379                                ││            │
        │  public:8081  admin:8082（各 1 副本，同机查库）           ││            │
        └───────────────────────────┬──────────────────────────────┘│            │
                                    │ 公网 + IP 白名单              │            │
        ┌───────────────────────────┴──────── B 机：轻量（北京）47.94.110.198 ────┘
        │  public:8081 + admin:8082（跨公网查 A 机的库）              │
        └─────────────────────────────────────────────────────────────┘
```

两条链只有两个方向：

- **B → A**：注册/心跳到 eureka:8761，查 mysql:3306 / redis:6379
- **A → B**：网关直连 B 的 8081 / 8082（地址来自名册里 B 自己注册的公网 IP）

入口永远只有 A 机的 80，B 不对外提供任何页面。

## 2. 两台机器的实际参数

| | A 机 | B 机 |
|---|---|---|
| 类型 | ECS `ecs.e-c1m2.large` | 轻量应用服务器 |
| 地域 | 华东1（杭州） | 华北2（北京） |
| 规格 | 2 核 4GiB / ESSD 40GiB | 2 vCPU 2GiB / 40GiB |
| 系统 | Ubuntu 26.04 | Ubuntu 24.04 |
| 公网 IP | `47.99.174.185` | `47.94.110.198` |
| 私网 IP | `172.31.5.80` | 无（轻量无 VPC 概念） |
| 带宽 | 100Mbps 峰值，按流量计费 | 200Mbps 峰值 BGP，不限流量 |
| 部署目录 | `/opt/blog-compose` | `/opt/blog-worker` |
| compose 项目名 | `blog-compose` | `blog-worker` |
| 成本 | 按量/包年 | ¥68 / 1 年 |

ECS 与轻量是两种产品、跨两个地域，**内网绝无可能互通**（阿里云客服已确认），所以整套方案建立在公网 + `/32` 白名单之上。

## 3. 端口与访问控制全表

### 3.1 A 机 ECS 安全组（入方向）

| 端口 | 用途 | 来源 |
|---|---|---|
| 80 | 站点入口 | `0.0.0.0/0` |
| 3306 | MySQL，B 的 public/admin 查库 | `47.94.110.198/32` |
| 6379 | Redis，B 的会话/缓存 | `47.94.110.198/32` |
| 8761 | Eureka，B 注册与拉名册 | `47.94.110.198/32` |

### 3.2 B 机轻量防火墙

| 端口 | 用途 | 来源 |
|---|---|---|
| 22 | CI 部署（runner IP 不固定） | `0.0.0.0/0` |
| 8081 | public 被 A 机网关调用 | `47.99.174.185/32` |
| 8082 | admin 被 A 机网关调用 | `47.99.174.185/32` |

80 / 443 已关闭，B 不跑 nginx。

### 3.3 三条硬约束

1. **网关所在机器必须能访问所有业务副本的 8081/8082**
2. **业务副本必须能访问 mysql / redis**
3. 端口映射写在 compose 里 → **改了必须重建容器才生效**（`mysql` / `redis` 不在 CI 的重建列表里，需手工 `docker compose up -d mysql redis` 一次）

## 4. 两份编排的差异

| 服务 | `deploy/compose-main.yml`（A） | `deploy/compose-worker.yml`（B） |
|---|---|---|
| nginx / gateway / eureka / mysql / redis / migration | ✅ | ❌ |
| public | ✅ 1 副本 | ✅ 1 副本 |
| admin | ✅ 1 副本 | ✅ 1 副本 |
| 数据源 | 容器服务名 `mysql:3306` / `redis:6379` | A 机公网 `47.99.174.185:3306` / `:6379` |
| 注册中心 | `http://eureka:8761/eureka` | `http://47.99.174.185:8761/eureka` |
| `EUREKA_INSTANCE_IP_ADDRESS` | 不写（默认容器 IP，A 网关同网络可达） | **必须写 `47.94.110.198`** |
| `depends_on` | 有（eureka/mysql/redis/migration） | 无（本机没有这些服务） |
| `container_name` | 只有 mysql/redis/nginx 写 | 一律不写 |
| `SPRINGDOC_ENABLED` | `false` | `false` |

B 机的 `EUREKA_INSTANCE_IP_ADDRESS` 是这套方案最容易漏的一行：不写就注册成容器内 `172.x`，A 机网关连不进来，表现为「名册正常但一半请求 500」。

## 6. CI 流水线结构

文件：`.github/workflows/deploy.yml`，单 job、push main 触发。

| # | 步骤 | 作用 |
|---|---|---|
| 1 | `Setup SSH` | `webfactory/ssh-agent` 同时装载 A、B 两把私钥 |
| 2 | `Add servers to known hosts` | 两台各 `ssh-keyscan` 一次 |
| 3 | 构建并推送镜像 | 6 个后端镜像 + 前端 nginx 镜像 |
| 4 | `Sync compose file` | scp `deploy/compose-main.yml` → `/opt/blog-compose/docker-compose.yml` |
| 5 | `Deploy backend`（A） | `pull migration eureka gateway public admin` + `up -d --remove-orphans` |
| 6 | `Sync worker compose` | scp `deploy/compose-worker.yml` → `/opt/blog-worker/docker-compose.yml` |
| 7 | `Login to ACR on worker` | 密码走 stdin，每次重登一次防失效 |
| 8 | `Deploy worker`（B） | `pull public admin` + `up -d --remove-orphans` |
| 9 | `Verify worker` | 轮询 8081 与 8082，最长 100 秒，失败时打日志 |
| 10 | `Deploy frontend` | A 机 `pull nginx` + `up -d nginx` |

顺序设计：A 先、B 后，避免「B 跑新代码、A 还没发版」。代价是 A 的 public/admin 重建到 B 跟上之间有 1 分钟左右的实例缺口。

### 所需 Secrets

| 名称 | 内容 |
|---|---|
| `SERVER_IP` | `47.99.174.185` |
| `SSH_PRIVATE_KEY` | A 机部署私钥（原始 PEM） |
| `B_SERVER_IP` | `47.94.110.198` |
| `B_SSH_PRIVATE_KEY` | B 机部署私钥（原始 PEM，**不能是 base64**） |
| `ACR_USERNAME` | 阿里云账号名 |
| `ACR_PASSWORD` | ACR 固定密码 |

B 机上 `authorized_keys` 存的是对应公钥，指纹 `SHA256:m8dgW0VTKcIUMf3qcYMeurAVXV1H8Ha4MeNduVe4cQo`。

### CI 不负责的事

- **不跑数据库迁移**：表结构变更仍要在 A 机手动跑 migration 容器
- **不重建 mysql / redis**：改动这两个服务的配置（含端口映射）要手工 `up -d`
- 不处理镜像清理，磁盘满了手工 `docker image prune -f`

## 7. 实测数据（2026-11-24）

| 场景 | 结果 |
|---|---|
| 外网读接口 10 次 | 耗时两档：A 副本 0.18~0.27s，B 副本 0.36~0.40s |
| 差值来源 | 每次查库一次杭州↔北京往返约 30ms 累积 |
| 停掉 B 副本立刻请求 | `500 200 500 200 …` 交替 |
| 全量恢复 | 90~120 秒（Eureka 90 秒租约 + 网关 30 秒缓存刷新） |
| 重新拉起 | 45 秒内名册恢复，耗时恢复两档 |
| 失败码含义 | 500 = 网关正常、连的后端拒绝；502 才是 nginx 认为网关挂了 |

## 8. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 名册有实例但一半请求 500 | B 的 8081/8082 未映射，或防火墙没放行 A 机 IP | 查 `ports:`、查轻量防火墙 |
| 名册里的 ipAddr 是 `172.x` | 漏 `EUREKA_INSTANCE_IP_ADDRESS` | 补 env 后重建容器 |
| B 容器反复重启，日志连库超时 | 还写着服务名 `mysql` / `redis` | 改成 A 机公网 IP |
| `nc`/`/dev/tcp` 卡满 3 秒失败 | 包被丢，安全组或防火墙没开 | 对比第 3 节表格 |
| 秒返回失败 | 端口通了但没人监听 | 容器没重建，或服务没起来 |
| 部署后全站 503 约 90 秒 | eureka 被 CI 重建，名册清空 | 接受，等副本重新注册 |
| CI 在 `Sync worker compose` 报 `Permission denied (publickey)` | Secret 里的私钥与 B 的 `authorized_keys` 不配对 | `ssh-keygen -lf` 比对指纹 |
| B 机 `docker compose` 报锁文件权限 | 没用 root | `sudo -i` |

自检连通性（B 机没装 nc，用 bash 内建）：

```bash
for p in 3306 6379 8761; do
  timeout 3 bash -c "echo > /dev/tcp/47.99.174.185/$p" 2>/dev/null && echo "$p OK" || echo "$p FAIL"
done
```

## 9. 已知取舍与未做项

| 项 | 现状 | 说明 |
|---|---|---|
| MySQL / Redis 单点 | 只有 A 机一台 | 多机只冗余了计算，数据库仍单点；主从是另一件事 |
| Eureka 单点 | 单节点，重启 90 秒空窗 | 要消除得配 peer 集群 |
| 网关自己也注册 | 名册里多一条 `BLOG-GATEWAY` | 收紧方案：网关注册 `register-with-eureka: false`，public/admin 拉名单 `fetch-registry: false` |
| 密码仍是 `root1234` | 未改 | 3306/6379 对公网开放后，白名单是唯一屏障，建议单独一次改动（涉及 A 的 mysql/redis + public/admin/migration 共 6 处 env） |
| B 的 22 对全网开放 | CI runner IP 不固定 | 要收窄只能固定 runner，暂不划算 |
| 跨公网延迟 | 一半请求慢约 0.15s | 博客量小可忽略，是这台北京机器的固有代价 |

## 10. 降级与回滚

**只停 B 机（回到单机）**

```bash
cd /opt/blog-worker && docker compose down
```

90 秒内名册剔除 B 的两条实例，网关回到只打 A 机，不需要改任何代码或配置。

**A 机到期、换小机器**（此方案的前置演练目标）

- 把 mysql / redis 一起搬到 B：A 只留 nginx + gateway + eureka（约 500MB 内存，1C 就够）
- 所有地址都在 compose 的 `environment` 段，改 IP 即可，代码不动
- 唯一硬约束仍是第 3.3 节那三条

**B 机到期、换新机**

改 B 的 compose 里 4 处地址 + `EUREKA_INSTANCE_IP_ADDRESS`，重跑 CI 即可。

## 11. 从零复现的顺序

1. 买机器 → 记录公网 IP、装 Docker（国内建议走 apt：`apt-get install -y docker.io docker-compose-v2`，`get.docker.com` 脚本可能 TLS 被重置）
2. A 机安全组放行 3306 / 6379 / 8761，来源 `B_IP/32`
3. B 机防火墙放行 8081 / 8082，来源 `A_IP/32`
4. B 机 `docker login` ACR 一次
5. A 机：`docker compose up -d mysql redis`（让端口映射生效）→ 再完整 `up -d`
6. B 机：`docker compose up -d public admin`
7. 查名册两条、外网连打 10 次看耗时两档
8. 接 CI：加 `B_SERVER_IP` / `B_SSH_PRIVATE_KEY` 两个 Secret，B 机登记对应公钥
