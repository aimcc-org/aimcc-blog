## 三、已确定的技术决策

1. **模块化推进**（用户明确要求：一个模块一个模块做，慢慢来）
2. 数据库 **4 张表**：`article`、`tag`、`article_tag`、`profile`。**category（2026-09-21）与 project（2026-09-22）先后砍掉**——理由一致：设计图有、真实需求无（两人团队无分类需求、无项目可展示）
3. 表间**不建物理外键**，只存对方 id（逻辑关联）
4. **接口返回不直接吐 entity**，用 VO（`dto` 包）；entity→VO 手写逐字段转换（新手阶段求编译期安全，不用 BeanUtils.copyProperties）
5. 文章「**阅读时长**」：发文时按字数自动算（中文 400 字/分钟 + 英文 200 词/分钟，向上取整，最少 1 分钟）——二阶段发文功能里实现
6. 明确**不做**：评论系统、Elasticsearch（用 LIKE）、Redis、点赞收藏
7. 主键自增 BIGINT（`@TableId(type = IdType.AUTO)`；个人博客无需雪花 ID，且雪花 ID 返回 JS 有精度问题）
8. **view_count 保留**（用户 2026-09-19 确认；更早会话一度按「砍掉」处理过，以本次确认为准）：article 表已有 view_count 列，详情接口浏览量 +1，hot 排序后续按浏览量改造
9. **统一 API 前缀走 yaml**：`application.yaml` 配 `server.servlet.context-path: /api`，Controller 的 `@RequestMapping` 不写 `/api` 前缀；外部 URL 不变（仍是 `/api/xxx`）
10. 分页插件：pom 需额外引入 `mybatis-plus-jsqlparser`（3.5.9 起拆分）；`MybatisPlusConfig` 注册 `PaginationInnerInterceptor(DbType.MYSQL)`
11. MyBatis-Plus 日常用法已入门：`LambdaQueryWrapper`（查）、`LambdaUpdateWrapper` + `setSql("view_count = view_count + 1")`（原子自增，避免读回再写回的并发丢计数）、`selectPage` + `Page`
12. **SQL 大小写约定**：教学讲解用小写关键字（用户看着舒服），写进项目的正式 SQL 用大写
13. MySQL 密码走环境变量 `DB_PASSWORD`（IDEA 运行配置注入，yaml 里 `${DB_PASSWORD:}`）；数据库操作（建表/插数）由用户在 DBeaver 执行，AI 只给 SQL
14. **异常处理独立 `exception` 包**（不并入 `common`）：`BizException` + `GlobalExceptionHandler` 集中一处；理由——高内聚、防 common 变垃圾抽屉、目录自解释；全项目保持此约定

### 穿插模块：云服务器部署 ✅ 完成（2026-09-21）

- 服务器：阿里云**免费试用**轻量 2vCPU 1GiB（Ubuntu 24.04）；试用期结束需续费或升级 2C4G
- 链路：服务器上跑 init.sql 建库（专用账号 `blog@localhost`）→ Mac `mvnw clean package` 打 fat jar → `scp` 到 `/root/blog.jar` → systemd 服务 `blog` 常驻 → 控制台防火墙放行 8080 → Mac 浏览器公网验证通过
- **1G 求生调优三刀**：swap 2G（`/swapfile`，已写入 fstab 持久化）；MySQL 减配（`/etc/mysql/mysql.conf.d/zz-low-memory.cnf`：performance_schema=OFF、buffer_pool 64M、max_connections=30）；JVM `-Xmx256m`（固化在 blog.service 的 ExecStart）
- **踩坑实录**（教学价值高，接手必读）：
  1. SSH 报 `Permission denied (publickey)`——镜像默认禁止密码登录，从控制台网页终端写入 `/etc/ssh/sshd_config.d/00-enable-password.conf`（PasswordAuthentication yes + PermitRootLogin yes，注意 sshd 配置是**先读的赢**）并 `passwd root`；**控制台「远程连接」网页终端 = SSH 配坏时的保底入口**
  2. 普通账号写系统文件报 Permission denied → `sudo -i` 变 root；且 `sudo echo > 文件` 无效（重定向是当前用户在执行）
  3. java 裸跑没带 `DB_USERNAME/DB_PASSWORD` → 接口 500——**凡 500 第一动作翻日志**（当前用 `journalctl -u blog`）
  4. MySQL8 新账号默认 `caching_sha2_password` + JDBC 禁取公钥 → `Public Key Retrieval is not allowed`（已 `ALTER USER ... mysql_native_password` 解决；更现代的修法见待办小课）
  5. 密码前后不一致 → `Access denied`；排障手法：**先 `mysql -u blog -p` 验钥匙，再怀疑应用**（隔离验证）
- 密码纪律：服务器 root 密码、MySQL blog 密码不进 git、不进聊天记录；blog.service 内含 DB 密码，已 `chmod 600`
- **待办小课**（部署后优化）：① JDBC URL 现代化（删 `useSSL=false` 走 SSL，或加 `allowPublicKeyRetrieval=true`，可免去换插件）② 正规化：jar 挪 `/opt`、专用非 root 用户跑服务、SSH 密钥免密登录、关闭密码登录 ③ 域名 + 备案 + HTTPS + nginx（上线前）
  ——**用户 2026-09-21 拍板：安全类改造（①②）暂缓**（试用机 + 测试数据 + 将来换服务器，风险可接受）。**重启触发条件（三选一即触发）**：接入真实数据 / 绑域名正式上线 / 管理端写接口开工。①已并入下次重新部署顺带执行，不单独开课

### Flyway 迁移体系（2026-09-21 引入，init.sql 已退役）

- **schema 变更一律新增** `server/src/main/resources/db/migration/V<n>__<描述>.sql`（版本号后**双下划线**）；应用每次启动在**每个环境**自动对账执行——本地/服务器/未来新环境永不脱节，告别"哪边建过表"问题
- pom 三个依赖：`flyway-core` + `flyway-mysql` + **`spring-boot-flyway`**。⚠️ **Boot 4 大坑**：自动配置按技术拆分模块，不显式引入 `spring-boot-flyway`，`spring.flyway.*` 配置**静默失效**（IDEA 报「无法解析配置属性」是最早的线索；运行期不报错，纯静默）
- 存量库接入姿势：`baseline-on-migrate: true` + `baseline-version: 1`（已有 profile/article 的库标记为「V1 已完成」，从 V2 开始跑）；对账本 = 各库的 `flyway_schema_history` 表
- 配套知识：终端 `mvnw package` 要加 **`-DskipTests`**——Flyway 让数据库变成启动硬依赖，脚手架冒烟测试 `ServerApplicationTests` 会因终端缺 `DB_PASSWORD` 连库失败；测试平时在 IDEA 里跑（运行配置有钥匙）
- 黄金规则：**已执行过的迁移文件永不修改**（改了会导致各环境校验和不一致）；要改就新增 V 文件
